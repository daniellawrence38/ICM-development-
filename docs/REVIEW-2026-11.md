# WWNet review: UX, isolated features and duplication (2026-11-23)

Scope: the whole repository at `e107482`. Read: Rust crates (core, design, sim, rules, hydraulics, py, cli), the ArcGIS
toolbox, the QGIS plugin and shared core, the assistant, schema and CI. Verified by running the CLI on a copy of
`examples/demo/demo.gpkg` (bug B1). Nothing was run in ArcGIS Pro, so anything marked *Pro* still needs checking there.

## Top recommendations (in order)

1. Fix `wwn_issues` growing on every design run (B1). Small Rust change.
2. Fix the "not in the active map" layer matching once, in one place (B5, D11).
3. Delete the pure-Python fallbacks and the CLI fallback (D1 to D7). About 600 lines go, and so does the risk of the
   two implementations drifting apart. `wwnet_native` is already required for import, check, design and simulation.
4. Give every ArcGIS tool one "Model" parameter that defaults to the model in the active map (U1).
5. Save results as feature tables in the GeoPackage and style them from shipped `.lyrx` files (U2, U3). This replaces
   the temporary in-memory layers and most of the `arcpy.mp` symbology code.
6. Trace from the selected node or pipe, with an upstream flow summary (U6).
7. Name simulation runs, let the user pick a stored run, compare runs and plot the hydrographs (U7, U8).
8. Give the assistant flow-modelling tools and make applying its edits deterministic (I2, U12).
9. Move node-load resolution into one shared loading module before the pressure-side work starts (D8).

## 1. Bugs found during the review

**B1. `wwn_issues` grows on every design run (verified).** `design_file` calls `Model::append_issues`
(`crates/wwnet-design/src/service.rs:83`), while `check_file` replaces the table. On the demo copy, issue rows went
from 0 to 10, 20 and then 30 after three design runs, with only 10 distinct issues. Running Check Model then wipes the
design issues. What the table holds depends on the order the tools were run, and it fills up with duplicates. Fix:
add a `source` column (`check` | `design` | `import` | `simulate`) and replace only the rows from that source.

**B2. The README feature table is wrong.** `arcgis_toolbox/README.md:217-218` says the QGIS plugin has "Design run:
result in layer" and "Trace". The plugin only has New, Open, Check and the assistant (see I1).

**B3. Import Sewer Data reports the same defect twice, with different severities.** The importer warns
`missing_invert`, `non_falling_grade` and `invert_above_surface`. The model check that runs straight afterwards
reports `MISSING_INVERT`, `ADVERSE_GRADE`/`FLAT_GRADE` and `INVERT_ABOVE_SURFACE`, two of them as **errors**. The user
sees both lists in one run (see D9).

**B4. Run Design selects the failed conduits twice.** It selects them on the results layer
(`tools_impl.py:272`) and again on the model's conduit layer (`tools_impl.py:335`). The second path goes through
`find_layer_for`, which is the open "not in the active map" bug, so every run currently ends with a spurious warning.
Selecting on the results layer is enough.

**B5. The open layer-matching bug has three implementations behind it.** `_layer_obj` (`WWNet.pyt:43`),
`maplayers.find_layer_for` (`maplayers.py:150`) and `ArcpyTools.find_layer` (`arcpy_tools.py:96`) each resolve a layer
their own way (name, normalised `dataSource`, table name). Put this in `maplayers` once. When the user pastes the
`dataSource` one-liner from the handover, also try `layer.connectionProperties`
(`connection_info.database` + `dataset`), which doesn't rely on the shape of the `dataSource` string (*Pro*).

## 2. UX: ArcGIS toolbox (the primary front end)

**U1. Choosing the model.** Every analysis tool asks you to browse to the `.gpkg` file. Trace asks for a Nodes layer
instead, and the assistant asks for a context layer. Use one parameter type that accepts the WWNet group layer, any
`wwn_*` layer or a path, and fill it in `updateParameters` from the WWNet group in the active map. Over a working day
this removes more clicks than any other change.

**U2. Results don't survive a Pro restart.** The design and simulation layers are `memory\` feature classes rebuilt
from JSON (`build_results_fc`, `build_sim_fc`). The results are already stored in the GeoPackage, but as attribute
tables only. `wwn_results_conduits` also holds just a subset of the output: no ADWF, Table 4.4 or hydraulic capacity,
or pumped and total flow. Those values are buried in a JSON `messages` column (I5). Have Rust write
`wwn_results_conduits` and a latest-run `wwn_sim_links` as **feature tables** with the conduit geometry copied in,
and with every displayed field as a real column. Then Add Model To Map shows them, they persist, QGIS gets them for
free, and the memory-FC code and the "temporary, re-run after restart" caveat both go.

**U3. Ship the symbology as `.lyrx` files.** Building CIM renderers in code (`symbology.py`) has caused several of the
Pro-only failures so far. Author the styles once in Pro, ship them in the bundle and apply them with
`ApplySymbologyFromLayer` or `parameter.symbology` on a derived output. This also covers the layers that currently
get default symbols: sub-catchments, pump stations, rising mains and node loads.

**U4. Declare derived output parameters** (model path, results layers). Pro then adds outputs to the map itself, the
geoprocessing history shows them, and the tools chain in ModelBuilder.

**U5. The message tables are noise.** Run Design writes a fixed-width table of up to 300 conduits. The Messages pane
uses a proportional font, so the columns don't line up, and the summary gets buried. The same applies to the
simulation top-20 table and the proposals table. Keep the messages to the summary and the worst 10. The full table
belongs in the results layer (U2).

**U6. Trace.** The start-node value list holds every node id, which is unusable on a real model. Default the start
node to the node selected on the map, and allow starting from a selected conduit. Report the upstream connection
count and the ADWF and GSDF at the start point. That is the "select pipe, see upstream connections and flow" summary
already on the wish list, and design's `node_flows` already holds the accumulated values. Rust `trace` should also
return the conduits on the path; Python currently rebuilds them through sqlite (`gpkg.conduits_between`).

**U7. Simulation runs are anonymous.** A run is identified only by a UTC timestamp. Ten runs are kept, but only the
latest can be shown, and runs can't be compared. Add a run `label` to `wwn_sim_runs` (for example "existing x1.0" or
"ultimate x1.5"), a "Show Simulation Run" tool with a run picker, and a compare output showing the change in peak
flow and peak d/D per conduit. This is the minimum for the ICM comparison in the handover.

**U8. The stored time series are never shown.** `wwn_sim_series` is written but nothing reads it. Add a hydrograph
output: a line chart on the series table filtered by conduit (*Pro*: `arcpy.charts`), or at least a CSV export.

**U9. No tools for model settings or profile assignment.** `adwf_per_connection_lpd`, `peaking_factor` and
`default_profile` in `wwn_meta` can only be changed by editing the table by hand. Assigning a profile to node loads
or sub-catchments means typing a free-text `profile_id`, and ArcGIS has no value-map widgets. Add a "Model Settings"
tool and an "Assign Profile" tool (applies to the selected features, with a value list from `wwn_profile_info`).

**U10. Roughness defaults differ.** Design uses Colebrook-White with ks 1.0 mm. Simulation defaults to Manning
n 0.013. Default the simulation to `ks` (an equivalent n per conduit from the model's ks, already implemented in
`inp.rs:128`) so one roughness in the model drives both runs.

**U11. No progress feedback.** Import, Design and Simulate never call `arcpy.SetProgressor`, so a long SWMM run looks
hung. Add a step progressor (read, build, run engine, write, map).

**U12. Applying the assistant's edits isn't deterministic.** "Re-run with Apply ticked" calls the model again, and it
may propose different edits (the README warns about this). Save the last run's proposals next to the history file.
Then add "Apply the proposals from the last run", which writes exactly those after checking that each current value
still equals the recorded `old` value. This costs no tokens and gives no surprises.

**U13. Tool organisation and wording.**
- Verify Setup sits under "Assistant", although it checks the engine too.
- "Set Assistant API Key" also holds the CLI path.
- Tool descriptions still say "Run `wwnet check`" and "Run `wwnet design`", CLI jargon for a user who can't run
  the exe.

Suggested categories: **Setup** (Verify Setup, Settings), **Model**, **Data**, **Analysis**, **Results** (show run,
compare, hydrograph), **Assistant**.

**U14. Pipe Capacity accepts DN150 to DN600 only**, from a value list, while the importer handles DN100 to DN1200.
Accept any DN and run the DS 50 checks only inside their range, with one info line saying why.

**U15. Issues have no geometry.** Check Model's "output issues table" duplicates `wwn_issues` and can't be zoomed
to. Write issues as a point layer (the node location, or the conduit midpoint). Pro's attribute table then gives
click-to-zoom, and the QGIS dock can read the same layer.

**U16. Unsaved edits.** QGIS refuses to run Check while WWNet layers have unsaved edits. ArcGIS relies on a README
note. Add at least a one-line reminder to Check, Design and Simulate, and block if the edit state can be detected
(*Pro*).

## 3. Features developed in isolation

**I1. The QGIS plugin stopped at Phase 0/1.** It has new and open model, check and the assistant. It has no import,
design, simulation, trace or profiles. Recommendation: formally freeze it (fix the README and state that ArcGIS is the
primary front end). Move the host-agnostic orchestration out of `tools_impl.py` into the shared core: summaries,
result-row building, the simulation classes and issue counts. Parity is then cheap if QGIS is ever needed again. Don't
spend effort on QGIS parity now.

**I2. The assistant only knows DS 50, but the priority is flow modelling.** The system prompt is "an expert in DS 50".
The tools can't run design, simulation or trace, and they can't read `wwn_results_conduits` or `wwn_sim_*`. In
ArcGIS those tables aren't on the map, so `query_features` can't reach them either. As a result it can't answer "why
is C12 surcharging?". Add read-only tools as thin wrappers around `wwnet_native`: `design_summary`,
`get_design_result(conduit)`, `get_sim_result(object, run)`, `list_sim_runs` and `trace(node)`. Widen the prompt to
cover the simulation.

**I3. Simulation warnings are plain strings.** Check and design return structured `Issue`s (severity, code, object,
clause). Simulation returns free text, so its warnings can't go into `wwn_issues` or be navigated to. Use `Issue`.

**I4. Design and simulation disagree wherever there's a pump station.** Design routes the pump rate to the discharge
node. Simulation drops pump stations with one generic warning (`inp.rs:152`), so everything downstream of the
discharge is under-loaded in the simulation. Until the pressure side is built, warn per pump station with the flow
that goes missing, and say so in the run summary.

**I5. The persisted design results and the displayed results have drifted apart** (see U2). The front end ignores
`wwn_results_conduits` because it lacks the fields it shows.

**I6. The demo model is out of date.** `examples/demo/demo.gpkg` is schema v1, with no node loads, profile or
simulation tables, so it doesn't exercise the current workflow. Regenerate it with `wwnet demo` and include node loads
and the example profile.

| D4 | TOML parsing | `core/tomlmini.py` (209-line custom parser) for the rule set and the import template | Use `tomllib` (Pro is on Python 3.11), or have native return the rule set as JSON; keep `tomlmini` only for Python < 3.11 |
| D5 | Model create / upgrade | `schema.create_model` / `upgrade_model` (Python, packaged `schema.sql`) and `gpkg::create` / `upgrade` (Rust, compiled-in SQL). D1 to D7 together remove roughly 600 lines of Python and their tests, and remove a whole class of "works with native,
behaves differently without it" problems. Verify Setup becomes the single place that says whether the engine is
present.
